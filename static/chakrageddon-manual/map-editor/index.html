Map editor

Map Studio is a local tool for editing Chakra-geddon's maps and trying them in the game engine. It shows the game's tiles and props in a visual, searchable palette and lets you work across zones, trainers, dialogue and other data in one draft.

The editor is for a local copy of the game repository. It is not part of the published game and cannot be opened from the online game alone.

Start the editor​

  1. Install Node.js and open a terminal in the root of your local game repository.

  2. Run:

    npm run editor

  3. Open http://localhost:8081/editor in a browser. Keep the terminal running while you edit; stop it with Ctrl+C when finished.

The editor listens locally and writes to the data files in your repository. Use a copy or a version-controlled working tree so you can review or revert saved changes.

First edit​

  1. Select a Zone at the top. The central canvas shows the map; the left panel holds tools, the tile palette and preview controls. The right panel is the file inspector.
  2. Scroll the left panel down to Find tile and the palette. Each tile has a sprite preview, its character and a logic badge such as FLOOR, SOLID or ENCOUNTER. Search by character or sprite name, or browse the grouped tiles. Click a tile to select it.
  3. Choose Brush (B) under Terrain, then click or drag on the map. The brush size can be changed from 1 to 5.
  4. Click Pending changes to see a unified file diff. Use Undo or Redo to revise the draft.
  5. Click Verify draft and review the results below the map. Then try the map in Playtest before choosing Save.
tip

If you only want to select a map position for a playtest or analysis, choose Choose playtest tile first. Clicking with the brush or another editing tool selected may change the map.

Getting around​

Scroll the canvas area to pan, use the Zoom slider to change scale, or click the Minimap to center on an area. The toolbar's Zone selector switches between maps without discarding the draft.

Use the Tool menu for hollow rectangles, replacing all matching tiles, stamps, scatter, lasso, entity tools and more. Shortcuts do not switch tools while you are typing in a field.

Painting and arranging terrain​

  • Brush, Line, Filled rectangle and Hollow rectangle use the selected palette tile. Drag across the desired area.
  • Flood fill replaces a contiguous area. Replace all matching tiles replaces that character throughout the zone.
  • Stamp places a complete prefab, such as a shack, house front, vehicle or paired prop. Select a stamp and click its top-left tile; house width is configurable. To erase one, select Erase matching stamp, choose the matching stamp and a replacement palette tile, then click its top-left tile.
  • Scatter paints from weighted tile:weight pairs. For example, .:70 ,:15 o:10 b:5 favors . over the other three tiles. The weights are relative, not percentages that must add up to 100.
  • Select terrain makes a rectangle; Lasso terrain selects an irregular region. Use Copy selection, the flip buttons and Paste to place a copy, including in another zone. Move moves the selection and fills its old tiles with the selected palette tile. Selection operations affect terrain only, not NPCs, pickups or warps.

For structural edits, use Rows & columns rather than editing row lengths in JSON. Choose columns or rows, an index and a count, then Insert or Delete. Inserted cells use the current palette tile. The editor shifts supported coordinates and incoming references across affected files; deletion is refused if it would remove a referenced point or rectangle endpoint. Review the diff and verify connected zones after changing dimensions.

Preview the map​

The controls under Preview change the editor's view, not the saved game data:

  • Set the Festival clock, Tide, Active set, Intoxication, Wristbands and comma-separated Story flags to inspect different states. Selecting a set adjusts the clock and its prerequisite flags.
  • Turn on Logic overlay to inspect walkability, Entity and warp markers to locate objects, Trainer sight lines to see trainer vision, and Tall-prop occlusion to spot hidden staging.
  • Wraparound shades changes the sight preview; Route-hint connected areas, Fairy-ring links and Encounter terrain provide other diagnostic views.

Check important routes in more than one state: for example, before and after a story flag, at high and low tide, and at different intoxication levels. The route-hint areas are a convenience, not a complete simulation of a changing game.

Warps, rings and zones​

Link two exits​

  1. In Warp linking, set the arrival directions or leave them on AUTO. Choose One-way only for an intentional one-way exit.
  2. Select Link warp endpoints, then click the first exit tile.
  3. Switch zones if needed and click the second exit tile. Alternatively, click Choose target on mini-map and select the target in its preview.
  4. Review the resulting link and test it in both directions. Arrivals are placed one tile inward according to their direction. A pair of fairy-ring tiles in the same zone can be linked in the same way.

For a row or column of exits, select a contiguous strip and click Use selected row / column as warp strip, then choose the first target tile on the target preview. The target strip extends right or down, perpendicular to its inward direction. Reverse target strip order reverses the pairing.

Replace selected existing warps retains their advanced fields, but former counterparts are left in place and scripts may still refer to the old destination. Inspect those separately. Use the warp entity inspector for conditions and advanced fields such as closedIf, closedText, needs and scripts.

World graph​

Open World graph to view zone connections. Select a zone to open it, or select a connection to list its warps. Gold links have gates; dashed links connect interiors to their parents.

Use Create zone to add a draft zone, optionally cloning the current terrain or making an interior. Outdoor zones can be placed on the world map by clicking or dragging the pin. A terrain clone does not copy entities, warps or scripts: add an entrance before saving. Delete current zone checks for references; resolve remaining links and other references before saving.

NPCs, trainers, scripts and pickups​

  1. Under Entity inspector, choose NPC / trainer, Pickup or Warp.
  2. Select Inspect or add entity, then click an existing entity or an empty tile. Fill in the common fields or edit the entity JSON for advanced properties.
  3. For an NPC, use Edit trainer and team, Edit dialogue script, Edit highlines or Edit condition as appropriate. Apply the nested changes and then Apply entity to put them in the draft.
  4. Use Drag NPC or pickup to reposition an existing entity. Pick the matching entity type first.

In the trainer editor, Browse Astrals visually shows sprites, types and abilities and can be searched by name, ID, type or ability. Choose a species, adjust its level with the number or slider, and check its automatic move preview. Custom moves and a suggested reward are optional. Dialogue previews use the game's renderer.

Use Drag trainer sight on a visible trainer to set its facing and sight range. Set trainer walk-off target first selects the trainer and then its destination; the preview starts at the trainer's home position, so the real post-battle path can differ. For a visible non-trainer NPC, Resize NPC wander box selects the NPC and lets you drag a cyan corner.

Structured script forms cover common steps, while advanced steps can be edited as JSON. A script or trainer definition may be shared: changing it affects every reference, not just the NPC you clicked. Pickup IDs must be unique across zones. Verify the draft after changing entities, conditions or shared data.

Encounters and atmosphere​

Edit wild encounters edits the zone's encounter rate and its day, night and water tables, with weights, level ranges and applicable conditions. Probability bars are based on the configured weights; conditional entries may not all be available in the same playthrough.

Under Atmosphere geometry, choose a feature and add it at a selected map tile. Select an existing feature and use Drag atmosphere handle to move its cyan point, line endpoint or rectangle corner. Edit crowd / FX properties edits supported fields; advanced properties remain available in JSON. Deleting a selected part of an FX removes the entire effect, including its other points and lines.

UV tint, flash and blinking tile lights are zone-wide and do not need a map point. Blinking lights use the selected palette tile and can be changed in their properties. Story flag tiles and hallucinations have their own add and delete controls:

  • For a story flag tile, select a map point and replacement palette tile, enter the flag and choose Set flagged tile at selected point. Enable that flag in Preview to see the replacement; the underlying terrain is unchanged.
  • For a hallucination, choose its kind and add or edit it. Positioned effects use atmosphere handles; use Ego gone in Preview to see them. Echoes follow their NPC.
  • Edit tide and lane rhythm edits low-tide intervals and lane defaults. Select a map tile first to edit its lane-row overrides. Turning off a configuration removes that zone's entire tide or lanes object.

Playtest the draft​

  1. Choose Choose playtest tile, then click an unoccupied walkable tile in the current zone.
  2. Click Playtest or press P. Choose a starter, party loadout and wristband count; enable or disable repel.
  3. Click Start at selected tile. Use the normal game controls in the embedded game.
  4. Use the live playtest controls to adjust clock, intoxication, individual wristbands and infinite repel. Close the panel when finished.

Playtest uses a copy of the current draft. It does not write game progress to your personal saves, and changes made while playing do not edit the map draft.

Checking for softlocks and other problems​

Use the Verification panel below the map and the actions in the toolbar:

ActionUse it for
Verify draftCheck unsaved changes, including data, supported interactions, movement, gates, events and scenario saves.
Run regression testsRun the selected game tests against an isolated copy of the draft.
Balance auditSample a route with different starters and seeds for battles, survival and hydration.
Trainer auditSample trainer approaches and fights for the current zone.
Script auditSample scripts for the current zone; choose an NPC and state limit in the left panel to focus or deepen the search.

For a closer look at a potentially trapped area, select Choose playtest tile and click an arrival point. Then use:

  • Analyze directed snapshot for exits and directional movement in the fixed preview state.
  • Analyze trainer walk-ups for possible positions where a trainer blocks a route or entity.
  • Analyze push route to select a destination and search for a way through a subwoofer puzzle; Analyze push deadlocks searches configurations that may have no route to a warp.
  • Explore changing movement states for a bounded engine search that advances movement-related state, or Explore movement and interactions to include tile interactions and dialogue choices. Set the Movement search command limit first.

Click a diagnostic to focus on its location. Where a replay button is available, step through the recorded route and events on the map. A replay is tied to the draft and preview state used for the analysis; changing either can invalidate it.

Reading the results

These are practical, bounded checks, not a guarantee that every playthrough is safe. Some checks use synthetic arrivals, flags or high-level parties; others stop at battles, unmodeled actions or search limits. A possible finding needs investigation, and skipped or inconclusive means the check could not decide, not that the route is safe or broken. Test important changes in the real playtest as well.

For a command-line check of the saved repository data, run npm run verify:map from the repository root.

Drafts, JSON and saving​

The draft is held in the editor across zone and file changes until you save or leave the page. Pending changes shows what will be written, including changes to multiple files. Use Undo and Redo while working.

The File inspector on the right exposes the current zone and shared data files as JSON. After editing the text, click Apply JSON to apply it to the draft, or Discard unapplied JSON to abandon the text edit. An unapplied JSON edit must be resolved before other editor actions. Use the row and column tools for map dimensions instead of manually changing row lengths.

Save validates the draft before writing. If validation rejects it, fix the reported issues and try again. After a successful write, additional event, movement, scenario and regression checks run; a failure at that stage is reported after the files have been saved, so review and fix it rather than assuming the save was rolled back. If a file changed on disk since the editor loaded it, the editor asks you to reload instead of overwriting it; preserve any draft you need before reloading.

Once intentional edits are saved, Refresh scenarios can update scenario fixtures, screen snapshots and the service worker and check translation status. It asks for confirmation because it writes repository files. Review the resulting changes: if a later step fails, earlier steps may already have written files.
